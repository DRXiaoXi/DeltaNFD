## 使用方式

- 系统优化新增“管理自启动项目”入口，打开独立管理页。支持搜索名称、来源和启动命令，刷新列表，单项停用、按原始备份恢复，以及恢复本工具停用的全部项目。原 UP 推荐等栏目次序保持。
- 覆盖当前用户 Run、所有用户 Run、所有用户 32 位 Run，以及当前用户/公共启动文件夹的 `.lnk`、`.url` 快捷方式。RunOnce、服务、计划任务、MSIX 和启动目录其他文件不在本次管理范围；可打开 Windows 自带的启动应用设置继续核对。
- “登记存在”仅表示发现登记，不假称 Windows 一定启用它；Windows 的 StartupApproved 和应用自身开关不读写。停用不卸载、不结束程序，不自动推荐或批量停用，也不估算启动耗时。
- 操作通过默认取消的确认框后执行。只影响以后登录时的启动登记，仍沿用管理员、游戏已退出及页面所属后端的限制。页面加载、刷新、搜索与取消不修改启动登记。

## 备份、冲突与中断

- 原始备份保存在软件数据目录 `StartupItems/<id>.json`，不放启动文件夹。绑定实际用户 SID、固定范围和名称，先完整序列化、WriteThrough/Flush(true)、原子发布及回读，再修改目标；首份原始记录不被重复操作替换。归档保留原始 JSON 字节。
- Run 保留原始 REG_SZ/REG_EXPAND_SZ 和未展开的文本。快捷方式保存原始字节、创建/修改时间、支持的文件属性、Zone.Identifier 来源标记及 DACL；不解析或执行快捷方式/命令。快照不宣称包含所有 NTFS 元数据。
- 页面提交不透明 ID 与观察到的指纹，后端自行解析固定位置并重新核对目标和备份。发现不同的同名登记时阻止恢复，可显式选择“保留当前并归档旧备份”。没有备份时不创建猜测的启动项。
- Run 优先使用注册表事务；仅在事务打开阶段返回明确不可用错误时采用常规接口，事务提交失败不重试写入。常规注册表接口没有值级条件写入或外部进程锁，重复核对仍不能消除检查与修改之间的并发窗口；确认框提示先退出对应应用及更新程序，不承诺并发场景下绝不覆盖其他进程刚写入的值。
- 快捷方式使用 CreateNew 恢复，先恢复来源标记和 DACL 再写可用内容。删除绑定已核对的同一文件句柄，期间拒绝写入和替换；不会检查旧文件后按路径删除新文件。
- 写入提交后失败或结果未知保留原始备份和待核对保护，不自动重放。全局备份摘要/一键恢复、system.reconcile/system.recover 均包含自启动范围。自启动中断不能借其他系统优化范围解除阻塞；恢复需完整复检且该范围无剩余备份。正常确认保留当前状态仍沿用原人工核对路径。
