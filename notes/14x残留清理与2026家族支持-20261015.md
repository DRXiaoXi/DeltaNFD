# 14.x 残留清理与 2026 家族支持（2026-10-15）

## 背景（Beta0.917 用户机器实录，6 张截图转录见 vc14-runtime-diagnosis）

用户机器（14.51.36247 环境）暴露四个问题：

1. **"Microsoft Visual C++ 2026 Redistributable (x64/x86)" 残留登记无法处理**——无卸载命令、缓存不可核验 → 归 `unknown` 保留 → 因版本 14.51 持续报红，"修复部分成功但红条还在"。
2. **定向修复退出码 1638**（另一版本已安装）——2026 产品线 MSI 使用固定四升级码家族之外的新升级码，`Vc14Catalog.Families` 枚举不到 → 14.51 MSI 仍在 → 14.42 降级安装被 MSI 拒绝。
3. **全量重装后系统 DLL 仍 14.51**——MSI 文件版本规则不降级覆盖；更高版本文件曾由范围外产品持有，14.42 安装器静默跳过文件复制，登记层 14.42 但 `msvcp140.dll` 未对齐。
4. **扫描盲区**——HKCU 每用户登记不扫；`Version` DWORD 不读；Appx CRT 系统包（由 Windows 管理）因版本非 14.42 持续误报黄。

## 用户授权（2026-10-15）

- 备份后受控清理：v14 INF 包装与孤儿显示登记（自动并入重装流程）。
- Appx 系统包降为说明性条目，不进横幅。
- 放宽横幅标准：**红色只由真实安装的 14.x MSI 组件驱动**；包装登记与残留最高黄色；主页与运行库页必须一致（两页共用 Classify/Vc14Scan 聚合，天然同步）。
- **补充确认（用户）**："Microsoft Visual C++ 2026 Redistributable" 是以前版本工具安装的 V14 版本包装——即本工具历史足迹，不是微软发行的新产品线。据此：
  - 残留清理**提前到卸载完成后、基线安装前**执行（这些登记会阻止基线安装，是 1638 成因之一）；
  - v14 包装登记**缺少卸载命令不阻断清理**（旧版工具留下的登记常缺此值；有值但与固定模板不符仍保留）；
  - 卸载命令指向的可执行文件不存在时不按命令执行（必败），转清理路径评估。

## 实现

### 扫描与分类（Vc14Catalog）
- `RegistryViews()`：HKLM+HKCU 各 64/32 位视图统一枚举（4 视图）。
- `RegistrationVersion()`：DisplayVersion → BundleVersion → Version(DWORD 四段格式化) 回退。
- `Classify(name, version, installedMsi)`：非真实 MSI 的登记最高 Warning；`IsAppxPackage` 固定 Normal。
- `DiscoverMsiProducts()`（修 1638 核心）：枚举 `WindowsInstaller=1` 的 14.x 登记 → 从 LocalPackage 缓存 MSI 只读解析身份（名称/版本/发布者/架构/升级码）→ release CRT 名称正则（含 2026/v14）核验 → 纳入产品列表与卸载计划。身份核验失败的条目照旧走包装登记路径展示，不猜产品码。

### 重装流程（Vc14Reinstall）
- 卸载计划枚举改用 4 视图 + Appx 明确排除（说明条目）。
- Burn 包装：只要缓存签名核验通过即纳入 bundle 卸载（不再因"同架构组件已装"跳过——全量重装语义即清掉所有 14.x）。
- 卸载命令存在性检查：命令指向的可执行文件不存在时归 `unknown`（不执行必败命令），由清理阶段评估。
- **阶段顺序**：卸载全部 → 确认无 MSI 残留 → **残留登记受控清理**（清不掉会停止——不带着阻止安装的残留继续）→ 安装双架构基线 → DLL 对齐阶段 → 最终复检。
- **DLL 对齐阶段**：MSI 登记复检通过但 `VerifyInstalled` 失败时，对双架构执行原包 `/repair` 强制恢复文件版本后复检；仍失败则报明确原因（"更高版本文件可能被其他产品持有"）并停止，不误报成功。

### 残留登记受控清理（全新 Vc14ResidueCleanup）
- `Survey(scan)` 只读枚举残留并分类：
- `inf-legacy`：固定 v14 INF 包装（登记叶子键 `vcredist14_x64/x86` + INF 形状哈希核验 + 发布者有值须微软；卸载命令缺失不阻断，有值但与模板不符则保留）→ 可清理；
  - `orphan`：名称匹配微软 VC++ 可再发行包装正则 + 发布者微软（若有值）+ 无可用卸载途径 + 键值形状正常（无子键、值名白名单、无超大值）→ 可清理；
  - `keep`：MSI 仍安装 / Appx / ARM64 / 有卸载途径 / 形状异常 / INF 缺失或哈希不符 → 保留并说明原因。
- `Run()`：每项"重读复核 → 备份（登记 JSON 导出 + INF/PNF 字节级校验副本）→ 删除（叶子键非递归）→ 复扫确认未再现"；MSI 事务忙即停；备份失败即停；取消/失败保留证据与备份。
- 不碰：System32/WinSxS、Appx、有子键或白名单外值名的键、重解析点。
- INF 形状哈希沿用历史工具写入的固定值（去注释、压空白、AppName/AppVer/GuidMin/GuidAdd 动态字段替换为占位后 SHA256）。

### 主页同步（DashboardViewModel / RuntimePage）
- 主页判定逻辑未改（与运行库页共用 `Vc14Scan.HasAbnormal/HasWarning`，自动一致）；红文案补"组件"字样以匹配新标准（红只来自真实 MSI 组件）。
- 运行库页横幅标题、重装卡片说明、安装登记说明、确认弹窗全部同步新标准与自动清理说明。

## 外部审查问题修复（2026-10-15，GPT 复核发现 5 处）

1. **动态家族无法卸载（P1）**：`RemoveAsync` 的 msi 分支原只接受固定四升级码，动态发现的 2026 家族会抛"升级家族无法确认"。修复：新增 `Vc14Catalog.ReadAny`（不要求固定家族的完整身份核验：产品码/名称/版本/发布者/架构/升级码/名称正则），卸载前复核改用 `ReadAny`；`ReadDiscovered` 同步复用。
2. **带引号卸载命令解析错误（P1）**：`"C:\目录\uninstall.exe" /quiet` 截取后参数残留引号。修复：新增共享解析 `SplitUninstallCommand`（引号开头走引号闭合拆分，否则 .exe 或空格拆分），计划存在性检查、实际执行、清理评估三处共用同一解析。
3. **失效命令卡在清理之外（P1）**：计划阶段发现程序不存在转 unknown，清理阶段却只看命令字符串非空就保留，两头堵死。修复：清理阶段的"可用卸载途径"判定改为命令解析出的可执行文件实际存在（或缓存可核验），失效命令归入孤儿清理。
4. **同名登记备份互相覆盖（P1）**：备份目录只拼键名，HKLM/HKCU 或 32/64 视图同名键的 registration.json 会覆盖。修复：备份目录改为 `Hive-View-KeyName` 三段。
5. **正常 14.42 包装持续报黄（P2）**：非 MSI 登记一律 Warning，基线同版包装修复后主页仍黄。修复：`Classify` 增加 products 参数，与已核验同架构同版本 MSI 组件对应的包装登记为 Normal；Scan 调用处传入。本机实测两个基线包装从 Warning 变 Normal。

## 外部审查问题修复·第二轮（2026-10-15，GPT 复核发现 4+1 处）

1. **无路径命令误判失效（P1）**：`MsiExec.exe /X{...}` 等不带完整路径的有效命令，`File.Exists` 按当前目录查不到，会被当孤儿登记删除而真实组件仍在。修复：新增 `Vc14Catalog.UninstallExecutableAvailable`——相对名按 System32/SysWOW64/PATH 解析，绝对路径直接存在性检查；计划与清理两处共用。
2. **共用 INF 中途卡流程（P1）**：同一 v14 包装在两个注册表位置时，处理第一项即删共用 INF，第二项复验时因 INF 缺失变"保留"而停止；此时旧组件已卸载、基线未装，重试也无法继续。修复：`Survey` 增加跨轮累积的 `verifiedInfBases` 集合——本轮已核验（或已删除）的 INF 不再要求存在，同名登记仍可清理。
3. **四视图同名登记被漏（P2）**：卸载计划只按键名去重，HKLM/HKCU 或 32/64 视图的同名键（命令/版本可能不同）会被跳过。修复：去重键改为 `Hive:View:Key` 三段；已核验 MSI 的登记键单独跳过（MSI 上下文登记随卸载移除）。
4. **启动失败永久卡待核对（P2）**：写 prepared 后 `Process.Start` 明确失败（文件不存在等），记录保留为"启动结果未知"，核对入口对 prepared 永久阻断且无解除路径。修复：启动明确失败时（进程从未运行、无系统变更）归档为 `launch-failed`，不阻断后续操作；启动成功后的异常仍保留记录待核对。
5. **烟测假断言**：`|| true` 使断言永真。修复：替换为真实断言（2026 包装匹配清理正则、无关产品不匹配、无路径 MsiExec 可解析、不存在的程序判不可用、带引号缺失绝对路径判不可用）。

## 外部审查问题修复·第三轮（2026-10-15，2 处 P1）

1. **无路径命令执行后无法解除待核对**：`MsiExec.exe` 等相对名命令能通过存在性检查，但执行与活动记录仍存相对名；启动成功后超时/中断时，核对入口因"不是完整路径"拒绝记录，进程退出也无法归档。修复：新增 `ResolveUninstallExecutable`（按系统目录/PATH 解析为完整路径，`UninstallExecutableAvailable` 复用），`RemoveAsync` 的 registry 分支用解析出的完整路径启动——活动记录始终存完整路径。
2. **共用 INF 的跨运行重试仍会卡住**：已核验集合仅在内存，清理第一处并删除 INF 后中断重试会重建空集合，剩余登记因 INF 缺失被保留。修复：判定改为"INF 存在则核验形状；INF 不存在则仅清登记（叶子键名 + 名称正则 + 卸载命令模板 + 发布者四重核验已足够确认旧工具足迹）"——单次运行与跨运行重试语义统一，删除/备份均为幂等（文件不存在即跳过），原内存集合参数移除。

## 用户机器预期效果

- 2026 家族 MSI 进入卸载计划 → 卸载后 14.42 可正常安装（1638 消除）。
- DLL 版本未对齐时自动 `/repair` → 不再出现"部分成功后 msvcp140.dll 仍 14.51"。
- 残留登记在基线安装前被备份清理（不再阻止 14.42 安装，1638 成因消除）→ 红条（由 14.51 MSI 驱动）与黄条（残留）都真正消除；主页同步转绿。

## 边界（不做）

不删系统 DLL/WinSxS、不卸载 Appx、不用 `IGNOREDEPENDENCIES`、不自动关防护、不强杀安装器、不动 2005–2013/ARM64/DirectX；真实 14.51/v14 MSI 组件的红色策略不变。本次仅本地实现与验证，未打包、未发布。
