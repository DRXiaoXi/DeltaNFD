# NVuc 辅助小缓存与 ASD 识别修复

2026-11-12。用户截图是 621.14、一个 256MiB A 层文件和一个 1MiB 文件，要求这个场景正确判定 ASD。工作在 `_br222/s` 的 `codex/nvph-b-layer-detect` 开发分支，保留前轮 NVPH 探针与自启动功能；HEAD 仍为 `dd807c595126978c3f3bace937b6ab234abe9cde`，版本仍为 Beta0.932-RC2 / 0.9321。本轮未提交、发布或修改根产品源码。

## 现场证据与原因

- 只读检查截图中的原文件：主文件 268435456 字节、已用 265833927 字节、16716 条记录，识别为 A 层；小文件 1048576 字节、已用 79079 字节、85 条记录，记录链完整闭合。
- 上轮探针在结构校验阶段要求至少 200 条记录，导致把这个完整的 85 条记录小文件返回为 Ok=false。汇总又要求覆盖全部文件，因而显示黄色待确认；这不是检测到容量异常或已证实文件损坏。
- 先用独立 Python zstandard 只读交叉核对：85 条均为已知 v13 包裹，每条恰好一帧，85 帧全部成功解压为 NVuc 标签，解压长度 528–7584 字节，未发现 BC/STR 等混合载荷。原始样本和载荷不复制进源码；只读脚本和统计证据留在忽略的 `_buildcheck/nvph-small-auxiliary-20261112/`。

## 改动

1. 将“记录链完整”与“统计定层的最少 200 条”分开。少于 200 条的有效链保留其精确条数和已用区，不能仅因此显示结构解析失败；A/B 大容器原有统计门槛与读取上限保持。
2. 新增纯 NVuc 辅助小缓存类型：已知 1488 字节头、32 字节前缀、v13 包裹；物理文件和已用区均小于 4MiB，最多 4096 条，单条输入/输出不超过 128KiB，累计解压不超过 8MiB。逐条检查包裹长度、压缩方式、Zstandard 单帧边界、解压长度及 NVuc 标签，全部成功才接受。未知标签、损坏、串接帧和预算超限不能判绿；不能跳过未知首条记录后将后缀当成辅助容器。
3. 容量规则合规且存在 A 层，其余全部为 A 或已确认的纯 NVuc 小缓存、未检出 B 时，621.xx 显示绿色 `ASD已激活`。已确认 BC/STR/DXBC/ELF 的小混合容器仍作为 B 的正向证据；读取失败/未知仍不冒充 NVuc。原零文件、多版本、容量异常和非默认缓存设置优先级保持。
4. 细分明细中的“NVuc 辅助小缓存”“结构完整但样本不足”和“无法解析”。新增默认 false 的 IsLayoutUncertain 协议字段，仅为容量合规的纯层级未知提醒隐藏“去处理”；独立设置异常、读取失败、旧驱动等仍保留处理入口。旧载荷不会凭空获得这个标识，原枚举值不变。
5. 引用已缓存的托管 ZstdSharp.Port 0.8.8，只做有界 CPU 解压，不加载或执行着色器。MIT 许可证及第三方声明随完整运行目录提供。未复制私有研究代码、历史实验程序、样本或用户日志进入产品。
