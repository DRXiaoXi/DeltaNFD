# NVPH 结构探针可复现误报修复

2026-11-12。本地分支 `codex/nvph-b-layer-detect`，基于 `dd807c595126978c3f3bace937b6ab234abe9cde`。用户在原理检查后要求修复可复现问题；本轮未提交、上传或发布，版本保持 Beta0.932-RC2 / 0.9321。

## 修复行为

1. ASD 正向布局提示要求确有 Pso/A 层，所有被检查 NVPH 都成功定层，且未检出 Bytecode/B 层。无法读取、结构失败、未定层都不再作为排除 B 层的依据，保留黄色 Warning/Unspecified，并显示“ASD 状态待确认”。额外非零文件仍允许存在，不仅因中间文件判为损坏。
2. 已经检出的 B 层保留其正向结果，其他文件未知不抹掉该证据。原多 GameVer、零文件、容量布局等异常仍优先；621 旧布局黄色且无不必要清理入口的行为保持。
3. 标记搜索只有在整条记录链验证通过后才接受当前标记。前面的假标记失败后继续查找后续候选；同一标记存在多种合法前缀解释时拒绝任选其一。后续真实记录不作为与最早合法链竞争的另一个容器头。
4. 使用 ReadExactly 读取记录前缀，维持单链最多200000条及所有候选合计600000次记录读取预算。超过单链上限立即返回未知，防止从第二条记录起解析后缀绕过上限。
5. 汇总明细分别统计 A、B、未定层和无法解析数量。文案改为“检测到/未检出 B 层数据”，不将静态存在直接称为“仍在写入”或“已退出”。12KiB 平均占用、4MiB 小体积门槛及200条最低记录数保持，仍然是经验结构推断；没有读取真实 ASD 开关、解压验证内容或证明运行实效。原 OS build 说明未新增功能检测。
