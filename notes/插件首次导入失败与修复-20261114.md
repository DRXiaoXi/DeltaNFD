# 插件首次导入失败「插件安装根不存在」诊断与修复（2026-11-14 晚，本地 r4）

## 1. 现象

用户在 Windows 10 x64（VMware）里用 Alpha0.935（r3 安装包，显示 `Alpha0.935+f8ff08ac`）导入 DPC 计时器常驻插件包，宿主「拓展插件」页弹出：

```
导入失败
插件安装根不存在。
```

随附应用日志 `app_2026-11-14_19-22-31.log`：

```
19:22:58.144 [INFO ] 插件导入结果：success=False；message=导入失败：插件安装根不存在。
```

## 2. 根因

宿主 `PluginPackageImporter.ImportCore` 在开始导入前要求插件根目录已经存在：

```csharp
if (!Directory.Exists(pluginsRoot)) return PluginImportResult.Fail("插件安装根不存在。");
```

而 `pluginsRoot` 固定为 `%LOCALAPPDATA%\Delta NFD\Plugins`（`PluginManagerService.DefaultPluginsRoot`），以下位置都不会预先创建它：

- `PluginManagerService` 构造函数只计算路径，不建目录；
- `PluginViewModel.Import` 直接把 `_manager.PluginsRoot` 传给导入器；
- `PluginPackageIndex` 只在写索引时创建自己的父目录，导入器在此之前就返回失败。

因此**全新用户/全新数据目录的第一次插件导入必然失败**。此前各轮交付的插件都只验证了「真实导入器接受包」（测试里会先 `Directory.CreateDirectory(pluginsRoot)`），真实 GUI 导入路径一直标注为「未验收」，这个缺口直到本次 VM 实测才暴露。

## 3. 证据

1. r3 安装包内嵌的 `DeltaNFD.dll`（2610688 字节）中存在旧错误串「插件安装根不存在。」（UTF-16 偏移 2021330），不存在新逻辑串。
2. 用 r3 发布布局的 `DeltaNFD.dll` 加载真实 `PluginPackageImporter`，对一个**尚未创建**的插件根导入真实 `.dnfdplugin`：

   ```
   SUCCEEDED=False
   ERROR=插件安装根不存在。
   ROOT_EXISTS=False
   ```

   与用户 VM 报错完全一致。
3. 同一探针改用 r4 发布布局的 `DeltaNFD.dll`：

   ```
   SUCCEEDED=True
   ERROR=
   ROOT_EXISTS=True
   ENTRY=io.github.drxiaoxi.dpc-timer-hold 1.0.0
   ```

   即修复后的宿主在首次导入时会自动创建目录并成功写入索引。

## 4. 修复

### 4.1 产品运行逻辑（唯一一处）

`src/DeltaNFD/Services/Plugins/PluginPackageImporter.cs`：插件根不存在时自动创建，而不是直接拒绝。

- 创建前先检查所有已存在的父目录不是重解析点（符号链接/目录联接），避免把插件写到链接目标；
- 创建失败（IO/权限/路径非法）返回明确错误「插件安装根不存在且无法创建：…」；
- 其余导入流程（暂存、重解析点检查、限额、路径越界、替换、原子提交）保持不变。

### 4.2 构建脚本（与产品运行无关）

`installer/publish-selfcontained.ps1` 有两处「调用同会话 PowerShell 脚本后检查 `$LASTEXITCODE`」的 gate：

```powershell
& (Join-Path $repo 'tools/Check-DeploymentScript.ps1') ...
if ($LASTEXITCODE -ne 0) { throw ... }
```

同会话脚本调用不会可靠更新 `$LASTEXITCODE`（新进程里是 `$null`，或保留上一次原生命令的旧值），导致 gate 在 PS 5.1 下必然抛错、开发树无法打包。已改为 `if (-not $?)`。这是 DPC 源码/载荷分离轮引入的构建回归，不影响产品运行逻辑。

### 4.3 回归

- `--plugin-dpc-timer-checks` 新增「首次导入时插件安装根不存在也能自动创建」：**125 项全过**（原 124 + 新增 1）。
- `--plugin-import-checks`：**55 项全过**。

## 6. 立即绕过（仍用 r3 的用户）

r3 只需手动创建目录即可导入，无需换包：

```powershell
New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\Delta NFD\Plugins"
```

或资源管理器打开 `%LOCALAPPDATA%\Delta NFD` 新建 `Plugins` 文件夹，然后重新选择 `.dnfdplugin` 导入。`PluginData` 等子目录会由导入器/备份存储自动创建，不需要手动建。
