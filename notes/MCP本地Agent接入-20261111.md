# MCP 本地 Agent 接入（2026-11-11，本地未发布）

用户要求尽量开放现有功能，同时保留原权限和游戏运行限制。本轮基于已发布的 `_br201/s` 独立建立 `_mcp1/s`，只叠加本轮文件，未把根目录其他研究或历史未提交改动加入本地产品。版本保持 Beta0.932-RC1 / 0.9320，不覆盖已发布同版本附件。

## 成品与使用

- 完整自包含目录：`_mcp1/f`，入口 `DeltaNFD.exe`。需保留整个目录，MCP 宿主在 `Tools/Mcp/DeltaNFD.Mcp.exe`。
- 先自行退出正在运行的旧版，再打开此目录；单实例机制会激活既有旧版。设置 → Agent 接入（MCP）→ 开启本次接入 → 复制 Agent 配置。
- 配置也保存在 `_mcp1/Agent-MCP配置.json`，仅含本地程序路径；不同客户端按其要求合并配置。本轮未自动修改用户 Agent 设置。
- 查询、目录、提交、轮询、取消共五个 MCP 工具；目录112项，涵盖 GPU、系统、ACE、运行库、通用进程控制及应用高级流程。详细范围与参数以 `deltanfd_list_actions` 返回的 schema 为准。

## 保持的执行边界

MCP 默认关闭、不持久化。受控写入在主窗口确认，默认取消、三分钟超时；帧格与核对入口沿原完整 UI 流程。辅助宿主不执行系统优化，不启动或提权主程序。前端调用原 BackendCaller/BackendClient，保留游戏三态、管理员、目标、低内存、紧急策略、租约、写前记录、备份、复检与未确认核对。六后端和原执行实现源码保持。

NVIDIA ReBAR 警告由主窗口按实际驱动确认，Agent 不能伪造已确认标记；型号改变后的着色器提醒沿原会话。帧格原流程无逐项返回值，因此 MCP 保守返回部分结果与状态，不根据总开关认定全部成功。隐藏钟摆/忽略精度请求、任意 shell/注册表/文件写入、原始后端生命周期、直接 GPU 重载、低层恢复/归档和临时 Defender 排除项未直接开放。

每次接入串行处理，最多256条记录、16个未结束操作；相同 requestId 与完全相同参数在本次接入内去重。跨重启或重新开启接入不能依赖去重，未知结果应先核对。关闭接入取消排队/待确认项，已开始的后端写入继续沿原路径收尾，不因断连强杀或重放。

## 本机连接

官方 C# MCP SDK 2.4.0 的 stdio 宿主使用命名管道连接主程序，无 HTTP 监听。随机名称与令牌，2MiB 帧限制，核对实际管道服务端 PID、创建时间和程序路径。管道 ACL 只允许实际用户 SID、拒绝网络身份，显式中等完整性标签；客户端使用匿名模拟级别。

官方 .NET 8 源码确认 CurrentUserOnly 使用 token Owner；提升后可能成为 Administrators。因此改用实际 User SID，查询进程仅需 PROCESS_QUERY_LIMITED_INFORMATION，不读取管理员进程模块。标签在新建管道上单独使用 LABEL_SECURITY_INFORMATION / WRITE_OWNER 设置，失败即拒绝接入，不依赖启用安全审计特权。已实读实际 ACL 和标签，但本轮环境非管理员，真实普通 Agent → 管理员主程序的跨 UAC 联调尚未实测。

原构建把相对 OutDir/PublishDir 传给子项目会造成宿主放错目录，现 build 使用绝对 TargetDir，publish 先按主项目归一化路径。已验证默认 build 和默认相对 publish 的实际宿主位置。

已知接入、参数和权限错误用 MCP 错误返回具体原因。连接中断/超时明确提示查询原任务或核对，不认定未执行，不建议换 requestId 自动重试。
