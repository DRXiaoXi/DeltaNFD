# DPC 源码与私有载荷分离

用户提出安装包包含 DPC、GitHub 源码不包含它。核对原始 1.4.0 EXE 内嵌许可后，用户明确回复“暂无授权，先完成源码与载荷分离”。本轮只完成分离及构建门禁，未切换产品驱动、生成安装器、上传或执行内核代码。之后提出并坚持通过插件再分发；截至本轮结束仍无原厂书面授权，没有将 DPC 放入插件、安装包或公开源码。

## 已完成

- 新增公开 `installer/driver-payloads.json`，只记录 x64 原件身份与当前 `not-authorized` / `not-approved` 状态；不含驱动、公钥私钥或授权原件。
- `tools/driver_payloads.py` 提供公开索引检查、源码 ZIP 导出、外部私有输入的只读校验、许可/安全审查前置的私有成品输入和布局审计。源码 ZIP 使用规范 Git 索引字节、重建 SHA 清单，不隐式包含未暂存改动。工具不改产品 Git 索引、不下载/执行驱动，也不创建内核服务。
- `.gitignore`、`.gitattributes` 增加常用私有输入和 DPC 文件排除；CI 在依赖恢复前检查索引，工作树检查纳入同一内容审计。发布脚本结束前审计布局。直接手工 ISCC 仍需先显式审计，不冒称已拦截任意绕过构建脚本的打包方式。
- 除路径规则外，检查已知原始 EXE、x86/x64 SYS 的 SHA、DPC PE 标识及有限 ZIP/gzip 嵌套；包括插件 ZIP，但不声称能识别任意格式或混淆。已经提交到历史的内容不会因 ignore 自动消失。

## 原件与授权事实

用户提供的原始 DPC EXE SHA 为 `00a7c7b88877bf59dbaa70de734fcd3f287f1eb92caff4571a4c8e67a5dc0aca`。内嵌条款明确私人非商业使用与书面再分发许可的区别。x64 SYS 为 21232 字节，SHA `636519d3293feb6779f089865c8c59a0763e720afefbad46fdb164fc06b9127e`，本次只读 Authenticode 为 Valid。该结果不构成内核加载、反作弊兼容或分发许可。

已知 CVE-2025-51619 涉及该版本本地低权限蓝屏问题；厂商页面现称已停止提供。插件、安装包或单独压缩包只是交付形式变化，不会产生原厂授权，也不会修复内核漏洞。用户自备原件、本地导入的插件是另一种方案，本轮没有实现或加载该插件。

参考：原程序内嵌许可；https://www.thesycon.de/deu/latency_check.shtml ；https://nvd.nist.gov/vuln/detail/CVE-2025-51619 。

## 验证

- 15 项专项测试通过：重命名/嵌套载荷、压缩限额、索引被工作树覆盖或删除、源码 ZIP 字节/清单、保护已有输出、外部输入、许可和安全门禁。全部用合成文件及自有临时 Git 库，不操作产品索引。
- 既有维护测试 12 项中 11 项通过、1 项因宿主不能创建 junction 跳过。源码索引 929 文件审计通过；工作树含未忽略新文件的检查零错误/警告。
- 7 个真实 Git ignore 和 7 个 export-ignore 路径核对通过。初次 PowerShell 文本管道附带 CR 的探针已改为精确 NUL 输入，不将该初次结果当通过。
- 本地实际 SYS 只读核验通过，重命名后仍被源码检查拒绝；实际 `stage-private` 在复制前以“未授权”拒绝，未创建输出目录。原 r3 布局审计 DPC 数量为 0；r3 安装包 SHA `9a9f0e8e5e3ac5ddfd95857fa3ea9c0d365ca97ce80d6a0953dc4195023d7911` 保持。
- 第一轮测试在中文 Windows 路径出现 Git UTF-8/ACP 解码错误，修正显式 UTF-8 后全通过；失败日志保留。发布脚本只解析未执行，不需重编无变动的产品 C#。
