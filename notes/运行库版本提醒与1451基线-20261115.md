# 运行库版本提醒与 14.51 基线（2026-11-15）

本轮按用户要求移除日常界面的旧运行库兼容性评级，加入 14.51.36247 基线。仍为 Alpha0.935 / 0.9350，只修改源码、编译与验证，不生成安装器或压缩包。

## 版本展示与主页

- 主页不再常驻运行库一行，不再因 V14 名称、14.50/14.51 评估、防护开关、旧防护恢复记录或版本无法读取而显示运行库提示。只在读取到 C++ 14.x 版本低于 **14.44** 时显示黄色提醒及运行库入口；14.44 的任意构建、14.50、14.51 和后续 14.x 不触发此提醒。
- 新只读检查读取 x86/x64 的安装版本和系统目录内 vcruntime140.dll / msvcp140.dll 的文件版本。不调用旧 MSI 兼容性扫描或运行库防护状态；任一架构、已读核心 DLL 的已确认旧版本均可触发提醒。旧检测开关不会屏蔽新最低版本提醒。
- 缺失、格式无效、读取失败不能虚构成“低于 14.44”，也不称为已确认正常；主页不显示这类状态，运行库页保留版本信息与无法读取的详情。主页健康摘要不计入已隐藏的运行库状态。
- 运行库页删除旧红黄蓝兼容性评级和检测开关，使用独立 `RuntimeVersionText` 展示只读版本；旧 `DetectionStatusText` 绑定已退休。原 UI 文档检查断言未修改，33 项通过。安装前的完整 MSI 身份、共享依赖、占用、载荷和安装后文件核验仍保留，这些用于明确安装范围和防止误报修复成功。

## 安装与中断处理

仍先确认完整卸载/安装计划并耐久保存意图，再执行安装器；写记录失败时不操作。实际四个 MSI 身份及全部目标 DLL 复检通过后才归档续装记录；x86 失败、需要重启、取消、结果未知或文件版本不符均停止后续步骤并保留核对责任。安装后只返回退出码 0 不能证明修复成功。安全模式仍仅允许受控卸载，正常模式重新确认安装；不强制重启。

原安装器与新基线的实际执行没有在宿主或虚拟机进行。下面的安装成功、中断、续装、错误后复检为真实控制器配模拟安装器的测试；它们不能替代实际 Win10/Win11 安装、游戏兼容及不同机器验收，也不能保证绝无安装故障。

## 源码与构建输入

两套新 EXE 及八个 MSI/CAB 共 10 个输入在本地 Assets 中。项目复制与发布检查包含新目录；MSI/CAB 逐项哈希校验，运行时也会核对 EXE 哈希、版本和微软签名。二进制沿用现有依赖策略由 Git 忽略；源码保留身份与哈希清单。

新增 `tools/prepare-vc1451-media.py --x86 <原包路径> --x64 <原包路径>`（需要 WiX Toolset 5）：先核对两份固定 SHA，再用 WiX 静态提取，校验所有 MSI/CAB 后恢复构建输入。已有不同内容的目标拒绝覆盖；不运行原包、不安装 MSI 或修改系统运行库。短暂存路径避免 Burn 在长 checkout 下漏提取文件。6 组实测包括首次恢复、重复运行、部分输入续补、架构错误、改一字节的原包、保留不同内容的既有目标。
