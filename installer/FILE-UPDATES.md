# 文件级更新发布

客户端点击更新时比对完整文件清单的大小及 SHA256，仅下载变化内容的 gzip 对象。不依赖旧版版本号猜测本地文件，也不在每次启动时扫描全部文件。此机制是文件替换，不是二进制补丁。

## 更新方式与首次部署

- 设置 → 软件更新可选“仅替换变更文件”（默认）与“全量更新”；默认服务器为自建，已有明确保存的服务器选择保留。自建及 GitHub 均允许这两种方式，发布端须提供相应材料。
- 缺清单、缺更新器、清单/对象损坏或网络失败时自动尝试全量更新，并在确认框与进度中说明。取消直接结束；切换方式、服务器或通道后停止旧请求。文件更新成功时仍只下载变化内容，即使其体积较大也不改模式。
- 每次发布仍保留完整安装包、大小及 SHA256，供自动回退或用户主动选择全量更新。全量模式直接下载整包，不先获取文件清单/对象。自动回退不改写用户持久化的更新方式。
- 自动服务器模式按 GitHub → 自建服务器回退。手动指定服务器时，清单、对象、重定向及整包均遵守所选服务器，不恢复代理。服务器回退不改变用户选择的更新方式。
- 启动交接失败后，仅在更新器已退出且未替换文件或已经完成回滚时尝试一次全量更新。全量包不可用、校验失败或安装启动失败后停止，不循环重试；所有来源、版本、安装身份及安全交接门禁继续生效。

## 生成材料

先完成自包含发布及其完整安装包，使用现有 `make-update-manifest.ps1` 生成与本次安装包一致的 `update.json`，再执行：

```powershell
python tools/make-file-update.py `
  --layout _buildcheck/release-publish `
  --output _buildcheck/release-files `
  --base-url https://deltaxiaoxi.xin/updates/packages/NEW_VERSION `
  --installer-manifest _buildcheck/release/update.json
```

输出目录必须不存在；不得在发布目录内部生成。可选 `--previous-files <上一版 files.json>` 生成旧文件移除条目。只有本地旧文件仍匹配上一版 SHA256 才会删除；未知文件和用户修改过的旧文件保留。不得把用户配置/日志/插件目录混进发布布局。

材料包括：

- `objects/<原始文件SHA256>.gz`：按内容去重，gzip 字节可重复生成。
- `files.json`：所有产品文件的路径、原始大小/哈希、传输大小/哈希及地址。
- `DeltaNFD_Files_<三段数值版本>_x64.json`：与 files.json 完全相同，供 GitHub Releases API 发现，例如 `0.9192` 对应 `0.9192.0`。
- `update.json`：保留整包信息并增加 `fileUpdate` 描述；`build-result.json` 为本地统计。

GitHub 同步发布对象时增加：

```powershell
--github-object-base-url https://github.com/DRXiaoXi/DeltaNFD/releases/download/vNEW_VERSION
```

这会让对象地址优先 GitHub、其次自建站。将 `.gz` 对象以文件名直接上传 Release（不用 objects/ 前缀），并上传上述精确命名的清单附件和完整安装包。未提供 GitHub 对象地址时，“仅 GitHub + 仅替换”会提示不可用，可手动改选全量；不偷偷访问自建站。GitHub API 必须已提供清单附件的 SHA256 digest 才会启用其增量。

## 上传顺序

Alpha0.9193 → Alpha0.9194 更新测试使用独立内测发现地址 `https://deltaxiaoxi.xin/updates/internal/update.json`；公测发现地址仍为 `/updates/update.json`。Nginx 对两份发现清单均设置 `Cache-Control: no-store`，版本目录保持不可变缓存。两个测试安装批次首次启动初始化为内测、自建、仅替换，此后同一批次保留用户选择。0.9193 以 `-RuntimeUiEnabled false` 构建；0.9194 使用默认 true。不要用覆盖同版本文件改变功能。

仅在用户明确授权发布后：先上传不可变版本目录内的完整包及全部对象，再上传文件清单，远端校验大小/哈希并抽检下载，最后原子替换正式更新清单。不要覆盖同版本文件；修改内容必须升数值版本。已有 Nginx 静态站可直接提供这些文件，无需新增上传 API 或修改反馈服务。

GitHub 缺失对象会导致仅替换失败，不能先激活清单再慢慢补传。发布工具只生成文件，不会联网、上传或替换线上清单。

## 退出、替换与恢复

独立更新器位于 `Backends/DeltaNFD.FileUpdater.exe`。生产下载及恢复证据保存在 `%ProgramData%\DeltaNFD-FileUpdates\<会话GUID>`，目录仅管理员和 SYSTEM 可写。更新前把当前更新器及其自包含依赖复制至会话的 worker/，因此替换安装目录时不会覆盖正在运行的更新器。

主程序确认更新器 Ready 后才批准退出。更新器持有现有部署互斥锁，复用 DeploymentControl.ps1 的协作退出流程，不强杀用户程序/后端/安装器。全部旧文件备份通过哈希检查并落盘后，逐文件持久记录 Intent、替换、Done，再核对整个目标清单。新版只读启动探针在设置/帧格/后端初始化前退出；只有本次创建的无状态探针超时才允许终止它。探针成功后提交事务、更新卸载列表版本并重新启动工具。

文件替换或新版启动验证失败且已确认回滚时，更新器通过受保护会话中的一次性续接记录重新打开设置页，继续原来已确认的全量更新。记录绑定安装目录、原清单哈希、服务器/通道/方式、短期 nonce 与原批准，消耗后不自动重放；续接重新检查相同版本及安装包身份。更新器未停止、日志缺失或事务未回滚时不启动全量安装器，保留现场。用户主动取消不自动回退。

普通异常会尝试回滚。备份缺失、外部修改或文件占用使恢复无法完成时保留现场，不启动不完整目录。断电/进程被外部终止不会自动注册开机任务；下次增量拒绝覆盖尚未完成的事务。维护人员可以在管理员终端使用保留的旧 worker 执行恢复：

```powershell
& '<会话目录>\worker\DeltaNFD.FileUpdater.exe' --recover '<会话目录>' '<manifest.json 的 SHA256>' '<原安装目录>'
```

恢复必须与同一会话、安装登记目录、清单哈希和备份匹配，不能任意指定其他路径。已提交事务不回滚。也可使用完整安装包修复安装。当前保留会话及备份供故障核对，不自动清除未完成事务。

## 验证边界

`--file-update-checks` 在隔离临时目录测试真实文件替换、失败恢复和模拟 HTTP；Python 单测验证生成器。`--file-update-layout-checks <files.json> <发布目录>` 只读验证真实发布目录。自包含发布脚本继续验证运行时布局及六个后端只读启动。

测试不修改本机登记安装、不执行真实原地更新，也不代表服务器已部署增量材料。正式端到端验收应在独立安装测试机进行。
