# Windows 10：玩家自备 DPC EXE 的钟摆计划

本工具不提供、下载、复制、提取或直接驱动第三方内核文件。玩家自行准备原版 DPC Latency Checker 1.4.0 EXE，在钟摆页选择原件。接受的原件为306928字节、SHA256 `00a7c7b88877bf59dbaa70de734fcd3f287f1eb92caff4571a4c8e67a5dc0aca`。

自定义游戏模式也按同样的准备和保存门槛运行。帧格精度忽略对象会跟随设置中所选的游戏主进程EXE，按完整路径核验；同时运行的三角洲或同名其他目录程序不会纳入。DPC仍只由本工具持有和释放，游戏进程的策略权限、自检与回读限制不变。

原版DPC会自行安装/加载它的驱动，默认申请1.0000ms。本工具核对自己的进程、原版服务和当前分辨率，不直接读取该EXE内部的驱动授予值，也不把读数视为Sleep或游戏效果。原版不能通过此入口设置0.5ms。

“隐藏DPC主窗口”默认开启：核验成功后，每秒按原件进程身份与主窗口特征维护隐藏状态；取消开关可显示。启动核验阶段可能短暂显示原程序，错误/关于弹窗保留。只管理本工具启动且PID/创建时间/映像匹配的实例，不影响外部DPC或研究插件。后台进程仍正常存在于任务管理器。

隐藏后释放仍向已核验的原主窗口发送正常关闭消息，并等待进程退出和服务清理。关闭失败时尝试显示原窗口，保留释放记录；不强杀DPC。工具意外中断后，可重开并通过“释放并核对DPC”按原记录关闭隐藏实例。

另提供算法1、2：DPC仍固定持有1ms，由工具自己的候选进程申请更细值，并在另一个不申请精度的进程中测量Sleep。算法1复用三级搜索、重复和稳定侧选择，算法2复用空闲/标准/重载验证；算法代码与Win11共用。只有候选实际读数匹配、联合持有复验和释放均通过才保存。它不修改DPC或其驱动，也不把DPC的1ms读数冒充更细候选。

## 使用

1. 退出三角洲、旧研究插件和其他DPC实例；以管理员身份打开工具，进入钟摆计划。
2. 点击“选择并核验EXE”，阅读确认框。选择只记录路径，尚未运行原件；替换、清除选择会使旧检测结果失效。
3. “仅检测DPC（不保存）”只核对基础1ms；“检测并保存基础1ms”保存原有数值方式，不测Sleep或CPU负载。
4. 使用算法时，先关闭帧格并退出游戏，选择算法1或2，点击“扫描并保存最优值”或“快速扫描”。它会施加CPU负载并测量Sleep，可能耗时数分钟；可取消。失败、取消、来源变化或释放未确认时不覆盖原保存。

也可在“自定义分辨率与 Sleep 测试”输入0.5000～1.0000ms，点击“验证并保存自定义值”。验证联合持有、独立等待和释放后，帧格会使用自定义值；DPC仍固定申请1ms，额外数值由工具自己的进程持有。原自动扫描记录保留，可点击“使用原自动/基础值”切回。重新选择或清除DPC文件会使两类验证失效，需重新验证。

“测试手填值的 Sleep”和“测试自动最优值的 Sleep”均临时申请对应值，在独立且不申请精度的进程采样200次Sleep(1)，不施加CPU负载，也不切换帧格选择或覆盖扫描结果。界面显示请求、授予、前后读数与中位数、平均数、P95等；读数不匹配时不能把该批样本算作目标分辨率的结果。结束或取消后确认释放。基础1ms保存记录不作为“自动最优值”；系统授予、虚拟机调度或其他程序请求可能限制实测结果，Sleep值也不等于请求分辨率或游戏收益。

5. 完成当前原件的检测保存后，帧格页才显示钟摆联动项。开启帧格后按已保存方式保持DPC在后台：基础方式持有1ms，算法或自定义方式同时持有DPC与对应目标的额外请求；持有确认后自动核验并忽略三角洲自身精度请求，无需另开忽略开关。Win10策略能力自检、无请求进程时钟可达性与目标回读仍必须通过，失败如实显示。关闭帧格或退出工具时先恢复游戏策略，再释放请求。本工具不按名称强杀DPC，不接管外部实例或研究插件；自己创建的工具子进程按原管道生命周期停止。
6. 用户关闭DPC、服务变化或数值变粗后，不循环重新拉起。先关闭帧格、点“释放并核对DPC”，再重新检测。算法持有还会低频复验独立等待，未通过则释放并报告。

有记录却不能确认释放时，不删除记录绕过：记录保存在软件数据目录`PendulumDpc/owned-process.json`。本工具只向PID、创建时间和映像都匹配的自有进程请求正常关闭；遗留服务无法确认清理时保留原因，不直接停止/删除服务。启动意图已落盘但PID未落盘的中断，需要玩家关闭DPC并重启Windows后核对，避免重复启动未知操作。

## 风险和系统策略

DPC 1.4.0有已知的CVE-2025-51619本地蓝屏漏洞。有效签名不修复漏洞，也不保证反作弊兼容；需要在自己的Win10环境验证。系统拒绝旧驱动时查看原程序和系统错误；本工具不关闭Secure Boot、内存完整性、磁盘保护，不修改BCD、TESTSIGNING或证书，不自动重启。

首次安装新工具不包含第三方原件，不构成第三方授权。原始EXE留在玩家选择的位置，不进入工具安装包或GitHub源码。工具运行时会保持只读文件句柄，防止运行期间替换原件。

## 旧自研驱动实验环境

新版不自动续办旧的测试签名/证书准备，不再把自研SYS和公钥装入新包。此前自行开启的TESTSIGNING、导入证书和登记的服务不会被擅自改动，也不会自动关闭其他项目需要的测试模式。

如需退出旧实验环境，请先关闭帧格/旧工具，使用保留的原始`Setup-Driver.ps1 -Action Remove`按原记录卸载；核对原本状态后，按原实验说明处理精确公钥及测试签名设置，再手动重启。不要直接删除未知服务、驱动或备份。升级后的安装目录可能保留旧说明和脚本，用于旧环境清理；这不表示新版继续加载它。

Win11保持原扫描与持有路径，不需要DPC。基础Win10平台身份为`win10-dpc-exe-v1/`；算法结果另加`/algorithms-v1`标识，绑定系统版本、原EXE和完整路径。旧自研结果不能授权此路径，基础1ms记录不能冒充算法结果。切换算法下拉仅影响下次扫描，不重标已有保存的算法类型。实际游戏或反作弊兼容性需独立验证。
