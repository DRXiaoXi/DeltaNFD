# 三角帧不掉洲使用教程

更新日期：2026-10-26

## 适用版本

本教程对应 **Beta0.93-RC2 / 内部版本 0.9302** 的当前界面和功能，此版本通过公测通道提供。已发布的 Beta0.93 / 0.9300 与本教程可能存在差异，请以所用版本的实际页面为准。

三角帧不掉洲是面向 Windows 10/11 x64 和《三角洲行动》的优化与维护工具。功能可能修改 Windows、电源计划、显卡驱动配置或运行库；不同页面的生效方式不同。请先阅读页面说明、预览内容和确认提示。性能改善取决于硬件、驱动、游戏版本和使用场景，工具不保证固定帧率提升。

下文的推荐结合开发者使用经验与软件当前行为，重点解释每项功能解决什么问题、适合什么场景。按自己的设备选择并比较实际表现即可，不需要把全部开关都打开。

## 第一次使用

1. 启动工具并等待主页的组件检测和优化项目预读完成。部分系统操作需要管理员权限；若页面提示权限不足，先确认当前权限并按提示处理。
2. 打开「设置」，检查当前游戏目标和三角洲安装目录。使用三角洲时保持默认目标；要将工具用于其他程序时，开启「不玩三角洲辣」并选择该程序的主 EXE。登记多个三角洲安装目录后，着色器清理、ACE 清理、运行库防护等目录相关功能会按页面说明作用于登记目录。
3. 回到「主页」，确认当前游戏目标正确。用「重新检测组件」刷新着色器、ACE 和运行库状态，同时查看内存状态；若显示“未知”或“待核对”，不要把它当成已确认故障。三角洲运行或运行状态未知时，前三项体检会暂停，显示上次结果或暂停说明。
4. 建议先查看状态和备份，再逐项使用功能。除「系统优化」的批量开关外，许多页面会在点击应用或切换开关时直接执行；请以页面上的确认框和状态文字为准。

## 主页与导航

主页集中显示当前目标、一键帧格模式、组件体检、可用内存和优化项目预读。点击状态旁的操作按钮可进入对应栏目。窄窗口会改为单列布局，内容可向下滚动。

### 内存提醒与回收引导

内存状态里的“冗余”指系统可用物理内存，不是硬盘剩余空间，也不是虚拟内存容量。工具按三角洲是否运行采用不同阈值：未启动游戏时预留较多空间供游戏启动；游戏运行后，重点提醒剩余空间是否紧张。

| 三角洲状态 | 可用物理内存 | 显示 |
| --- | --- | --- |
| 未运行 | 不低于 8 GB | 绿色，正常 |
| 未运行 | 少于 8 GB | 黄色提醒 |
| 运行中 | 不低于 2 GB | 绿色，正常 |
| 运行中 | 不低于 1 GB、少于 2 GB | 黄色提醒 |
| 运行中 | 少于 1 GB | 红色警告 |

这里 1 GB 按 1024³ 字节计算；阈值按实际字节判断，显示值保留两位小数。游戏状态未知时显示待确认，读取失败时显示待核对，不套用正常或异常等级。游戏中其他组件体检暂停时，内存检测仍会继续。

内存黄灯或红灯时，可点「设置内存回收与帧格」进入对应位置。先开启「自动内存回收」，再开启「一键帧格模式」，两个开关都开启才会联动。如果帧格已在运行，先停用帧格再修改回收选项。主页检测和跳转本身不会清理内存；自动回收仍需满足持续内存压力和间隔条件，具体模式见下文。

### 栏目与游戏运行限制

左侧栏目按用途分组：

| 栏目 | 用途 |
| --- | --- |
| 系统优化 | 查看并应用 Windows 优化项目、虚拟内存设置及备份恢复 |
| 帧格 | 管理游戏期间的自动化帧数保障与临时系统设置 |
| 运行库 | 检查和维护 Visual C++ 运行库，管理运行库防护 |
| 进程管理 | 查看进程属性、设置规则及内存回收参数 |
| 显卡伪装 | 临时或持续修改显卡名称显示，并恢复原值 |
| NVIDIA显卡设置 | 管理三角洲专用的 NVIDIA 驱动设置 |
| 着色器 | 检查、清理或修复游戏与系统着色器缓存 |
| ACE相关 | 检查反作弊组件与环境；在符合条件时进行受控清理 |
| CPU实验室 | 查看处理器拓扑并配置 CPU / 电源计划调度 |
| 拓展插件 | 导入和管理插件包及其授权 |
| 设置 | 配置游戏目标、外观、更新、反馈和恢复选项 |

三角洲运行期间，显卡伪装、着色器、ACE 和运行库栏目不可进入；若正停留其中，页面会返回主页。三角洲运行状态未知时也会按受限处理。请完全退出游戏及相关后台进程，再点提示中的「重新确认」。系统优化仍可进入查看，但写入、还原、清理和虚拟内存修改入口会禁用。此限制针对三角洲，不随自定义游戏目标切换而取消；确认游戏退出后入口恢复，不会自动打开栏目。

## 系统优化

此页面有扩展优化项目和虚拟内存（页面文件）等内容。

### 批量应用优化项目

1. 选择需要查看或调整的优化分组。
2. 先读每一项说明和当前状态，再切换对应开关。
3. 开关只是记录选择；所有栏目中选中的项目会累计。确认后点击「应用更改」才会写入系统。
4. Defender、防火墙、VBS、Windows 更新等高风险项目会在应用时再次确认。关闭安全功能可能降低系统防护，请只在理解影响时操作。
5. 页面顶部的备份摘要可查看状态；需要撤销时使用「一键恢复」或对应条目的恢复入口。恢复按工具保存的原值处理，不等于恢复 Windows 出厂默认值。

「刷新状态」只重新读取实际状态，不应用选项，也不会替你发起还原。尚未应用的选择会保留；需要写入时仍要点击「应用更改」。

### 虚拟内存

选择目标盘符并填写最小/最大容量后点「应用设置」。当前页面要求最小值和最大值均不低于 16 GB；修改通常要重启电脑才生效。使用「恢复修改前配置」回到工具修改前记录，或使用「恢复系统托管」交给 Windows 管理。应用前检查页面文件所在磁盘和容量是否适合自己的设备。

## 帧格

「一键帧格模式」是帧格功能的总开关，主页和帧格页状态同步。开启后，已选功能会在本工具运行期间按游戏状态工作；关闭帧格或正常退出工具时，会停止相应自动化并尝试恢复临时修改。切换时请完成确认、核对和恢复流程，不要强制结束工具进程。

页面功能包括自动内存回收、游戏启动时重启 DWM、电源计划锁定、系统定时器、游戏进程禁用电源限制、前台调度、网卡/USB/PCIe 省电设置，以及适用于双 CCD 的调度联动。是否适用由页面状态、硬件和游戏运行状态决定；笔记本上的部分网卡/PCIe 选项会被禁用。

### 如何选择帧格功能

**自动内存回收**主要用于三角洲占用过多内存而出现卡顿的场景，尤其是 16 GB 内存设备。开启前先查看主页内存状态；回收范围与三种模式的选择见「进程管理」中的说明。

**游戏启动时重启 DWM**是针对异常占用的排障选项，不推荐日常主动开启。先在任务管理器观察 DWM（桌面窗口管理器）的 CPU 占用，只有发现异常高占用时再尝试。启用后每次游戏会话只自动重启一次，也可用「立即重启 DWM」手动处理。重启瞬间可能短暂黑屏或闪烁，全屏程序可能切回桌面。

**电源计划锁定**源于开发者过去遇到三角洲改动玩家电源计划的情况，用于防范计划再次被改动。它可以维持当前计划，也可以在开启帧格时切换到你选择的计划并锁定。锁定不只是保持计划名称，还会按开启时的快照纠正计划内容；因此先完成 CPU 调度与电源设置，再开启锁定。它不会替你判断哪套计划最适合硬件。

开发者建议玩家普遍尝试以下选项，逐项比较效果；是否执行仍受硬件支持和页面限制约束：

| 选项 | 设计目的与使用取舍 |
| --- | --- |
| 系统定时器 0.5ms | 游戏运行期间请求更细的计时粒度，用于响应与帧间隔表现调优；请求不等于保证获得固定帧率提升。 |
| 前台加速响应 | 临时调整系统调度参数，尝试改善资源争用时的响应表现；不等于直接提高游戏进程优先级。 |
| 降低省电延迟 | 临时关闭选定的网卡、USB 或 PCIe 省电设置，减少设备低功耗唤醒带来的延迟；可能增加耗电，笔记本不适用的网卡与 PCIe 选项会禁用，USB 选项仍可按页面使用。 |

「游戏进程禁用电源限制」调整目标游戏进程的执行速度节能状态；关闭帧格或退出工具时恢复原值，进程管理的手动设置和规则优先。双 CCD 联动需先到 CPU 实验室登记「帧格生效」。

### 恢复与退出

使用前请留意：

- 自动内存回收只在帧格运行期间按设定工作；可在进程管理中调整后台参数和排除名单。
- 「电源计划锁定」会按启用时的快照纠正该计划中被改动的设置，包括 CPU 实验室的异类调度项。游戏期间要调整电源计划，请先关闭锁定或停用帧格。
- 电源锁定或恢复记录出现错误、冲突、未知状态时，使用「恢复 / 核对电源锁定记录」和页面提示处理；不要清除记录来绕过恢复。
- 退出时如果出现后台运行提示，按提示决定是否保留窗口在托盘。退出过程可能需要时间来停止后台功能和恢复临时设置。

## 进程管理与 CPU 实验室

### 进程管理

在进程管理页搜索或选择进程，查看它当前的 CPU、GPU、内存、I/O 优先级、亲和性、CPU 集合及效率模式等属性。单次修改使用对应的「应用」按钮；需要在以后游戏启动时重复执行的设置，可创建并保存规则。请确认规则的程序完整路径、作用范围及其与游戏模式的优先关系。

调整后可以查看「当前属性与控制方」。使用「还原当前进程修改」撤销当前进程的工具修改；使用「核对记录」只读比较记录与当前值。外部程序改过的值会作为冲突保留，不会被盲目覆盖。「全部还原」用于退出前收尾。ACE 相关受保护进程的部分修改入口会被禁用，这是预期保护。

#### 内存回收为什么分三种模式

三角洲在 16 GB 内存设备上可能占用过多内存，挤压其他程序的可用空间并引起卡顿。回收会缩减进程工作集，不结束进程；工作集减少不等于程序的内存需求消失，后续访问仍可能回涨或发生换页。因此模式的区别不仅是回收强弱，也包括影响范围和性能代价。

| 模式 | 推荐用途 | 实际范围与保护 |
| --- | --- | --- |
| 普通 | 回收较温和，先尝试此模式；适合希望尽量减少对其他程序影响的玩家。 | 按工作集排序，使用单次数量上限；不检测进程 CPU 占用，不设工作集大小门槛。保护游戏、工具、系统、前台、ACE 受保护进程、排除名单及已有修改记录或已启用规则的进程。 |
| 稳洲 | 比普通模式回收范围更广，适合普通模式不足、仍存在内存压力时尝试。 | 跳过三角洲主进程、系统、ACE 受保护进程及有规则的进程（含停用规则）；其他进程可包含前台与工具自身。不使用普通排除名单或单次数量上限，不清空全局待备缓存、不强制写回修改页。不可访问、身份不明或冷却中的目标会跳过。 |
| 激进 | 回收范围最广，性能损耗最大，不推荐日常使用。 | 不逐个统计进程，直接请求全局工作集及低优先级待备列表回收；忽略逐进程保护与排除名单，可能影响三角洲、ACE、前台和系统。保留其他待备缓存，不强制写回修改页，但仍可能引起换页、磁盘读写增加或卡顿。 |

在「后台保护与回收」中设置内存占用阈值、模式、单次数量、间隔及排除名单。普通模式默认每次最多 5 个进程，可设为 1–256；另外两种模式不使用此数量上限。回收最短间隔默认 10 分钟，可设为 1–1440 分钟，修改后点击保存。

自动回收需内存持续高压至少 30 秒，并满足所设间隔；达到间隔不代表立即回收。保存参数本身不会启动自动回收，仍需在帧格页同时开启「自动内存回收」和「一键帧格模式」。手动回收可先点「预览可回收进程」，再选择目标执行；当前模式的范围与保护以页面说明为准。

### CPU 实验室

页面会检测处理器并展示适用的调度选项。它们用于改变游戏与其他任务的 CPU 调度安排，请按处理器类型选择。

#### AMD 单 CCD：排除 CPU0

开发者建议 AMD 单 CCD 玩家主动尝试「排除 CPU0」，目的是让游戏避开 CPU0，减少与该逻辑处理器上系统任务的争用。它限制的是目标游戏的亲和性，并不会把全部系统中断或内核任务强制迁移到 CPU0。

游戏未运行时也可点击登记，目标启动后由工具应用并持续保持；需要取消时点「恢复全部核心」。AMD 双 CCD 玩家如果不想隔离整个 CCD，也可以只使用此项。排除后游戏可用逻辑处理器会减少，实际效果应结合游戏表现判断。

#### AMD 双 CCD：游戏与其他进程分开

开发者建议 AMD 双 CCD 玩家尝试 CCD 隔离，让游戏集中在一个 CCD，可调整的其他进程使用另一个 CCD，减少双方争用。它通过亲和性安排进程，不会增加 CPU 核心，也可能增加发热与功耗。

选择「游戏 CCD」时：

- 普通双 CCD 由玩家自行判断金银 CCD。按开发者经验，可参考高负载时两个 CCD 的电压，倾向选择电压较低的 CCD；测试方法与最终选择由玩家决定，这只是选核参考，不是工具自动测得的性能排名。
- 两个 CCD 存在大小缓存差异的 X3D 型号，优先选择大缓存 CCD 运行游戏，不直接套用普通双 CCD 的电压选择经验。

选好后点击「应用双CCD调度」。「立即生效」会开始调整；「帧格生效」会登记为帧格联动，随后在帧格页开启对应选项并启动帧格。需要取消时点「撤销调度」。

#### Intel 大小核：优先 P 核负载

开发者建议 Intel 大小核玩家尝试「一键优先 P 核负载」，让 Windows 的异类调度策略优先考虑性能处理器。此功能修改当前电源计划：生效的异类策略为 0，异类线程调度策略及异类短线程调度策略为“首选性能处理器”（2），交流和电池设置同时调整。

这是调度偏好，不会关闭 E 核，也不会把游戏亲和性锁定为只有 P 核；不适用的硬件不能靠此选项变成混合架构。使用「还原已备份策略」恢复修改前设置。

调整 CPU 或电源策略前，先确认 AC/DC（插电/电池）设置和生效方式。帧格的电源计划锁定会维护计划内容，可能阻止修改或随后按快照改回；需要保留新策略时，先解除锁定或停用帧格。

## 显卡、着色器与 ACE

### 显卡伪装

开发者加入此功能，是因为三角洲对高端显卡设置的最低画质档位仍比较高。伪装成较低型号，旨在尝试降低游戏的最低画质、减少渲染负担，进而提高帧数。它适合愿意用更低画质换取帧数、但原有最低档仍不能满足需求的玩家。

此功能只改注册表中的显卡设备描述字符串，不更改 PCI 硬件 ID、驱动或显卡本身的性能。修改名称不等于硬件升级，游戏是否采用更低画质仍需进入游戏检查。选择预置或自定义型号后先核对本次将写入的型号，再确认执行。伪装或恢复需要重启电脑才完全生效。

临时模式可选择立即重载显卡（不重启）或重启生效并在登录后自动恢复原型号；立即重载可能黑屏数秒，正在运行的游戏或 3D 程序可能崩溃，按页面风险提示选择。永久模式会保留伪装，直到手动恢复。首次伪装会保存原值。若以前用其他工具伪装过，请先用那个工具恢复，避免备份错误。存在未完成的临时还原时，先使用「核对并完成临时还原收尾」。

### NVIDIA 显卡设置

这里的 DLSS、帧生成、Smooth Motion、抗锯齿、显存回退等设置写入三角洲专用的驱动配置，不影响其他游戏。修改选项后点击「应用更改」；对正在运行的游戏，建议重启游戏后确认效果。「全部恢复默认」会删除该游戏配置中相应设置的覆盖，让游戏或驱动重新决定设置。

如果页面提示驱动配置数据库为只读，先点「解除只读」，应用并检查设置后再决定是否锁回只读。锁定会阻止 NVIDIA App、驱动更新和其他工具改写该数据库，也会阻止本页继续修改。驱动不支持的选项会报错，不代表显卡故障。

### 着色器缓存

按开发者使用经验，将 NVIDIA 着色器缓存大小设为“无限制”可能引发三角洲频繁抽帧，因此推荐保持「驱动默认」。全局设置与三角洲程序设置都要检查；页面出现非默认提醒时，可按指引恢复默认。

如果游戏已经频繁抽帧、卡顿，可尝试清理游戏与系统着色器缓存，让游戏重新建立缓存；这是一种排障方法，不需要在每次启动前反复清理。清理后仍要完成重新编译和预热，再判断效果。

先在「着色器」页重新检测健康状态。PSOCache 是游戏目录中的三角洲着色器缓存；系统着色器缓存位于 Windows 或显卡驱动的缓存目录，两者不是同一组文件。根据检查结果进入缓存处理页，选定要处理的范围后再清理。

清理前完全退出三角洲及其他游戏/图形程序。被占用或链接路径可能被跳过。清理不可撤销；首次进游戏会重新编译着色器，首局或首次加载地图可能卡顿，应等待编译稳定后再进行正式对局。调整全局缓存大小会影响其他游戏；页面建议优先恢复驱动默认值。预热需要在游戏内完成，工具不能替玩家确认编译已结束。

### ACE 相关

按开发者经验，旧 ACE-CORE 组件过多可能产生冲突并引起掉帧，这也是加入数量检测与清理入口的原因。多个使用 ACE 的游戏可以共存，因此多个 CORE 文件本身不代表异常，需要结合电脑上实际的 ACE 游戏数量判断。

当前检测比较共享 CORE 文件数与去重后识别到的 ACE 游戏安装目录数，不再逐个读取驱动内容或通过哈希确认归属：

| 检测情况 | 提示含义 |
| --- | --- |
| 检测到 CORE，数量不多于已识别游戏数，且 CORE 已读取完整 | 绿色，数量正常；不要求逐驱动对应到具体游戏。 |
| CORE 数偏多，尚未有效手动关联游戏 | 黄色，先补充可能漏检的游戏目录。 |
| 已有有效手动关联，CORE 数仍偏多 | 红色，提醒排查过多旧组件及可能的冲突。 |
| CORE 数量无法确认，或尚未发现偏多但 CORE 读取不完整 | 待核对，不把未知数量直接判为过多。已读部分就已偏多时，仍按前述红黄规则提示并保留未读全说明。 |

在「ACE 游戏与 ACE-CORE 检测」中点击「添加游戏目录并检索」，选择具体游戏安装目录，工具会检索其中的 ACE 组件并保存目录；只有本次确实发现组件的有效关联才计入手动游戏数。重复目录不会重复增加数量，移除关联只取消检索记录，不删除游戏文件。其他游戏目录的检索提示仍会保留在明细里，但不会推翻已完整读取且不多于已确认游戏数的 CORE 数量结论。

数量提示用于帮助排查，不代表已确认每个偏多文件都应删除。页面还提供 ACE 组件扫描和虚拟化环境检测；按实际故障和预览范围选择处理方式。

三角洲运行期间，ACE 扫描会暂停。手动清理前完全退出游戏和 `sguard64.exe` 等反作弊进程；清理共享目录中的 ACE-CORE 文件可能影响多款 ACE 游戏。清理后先通过游戏启动器执行普通修复以补齐组件，再启动游戏。页面的“核对上次清理”用于检查上次事务，不会重新执行清理。

## 运行库

按开发者经验，不同运行库版本会影响三角洲的帧数和流畅度，因此本工具针对游戏表现推荐固定的安装基线，而不是简单地把版本号越大视为越好。当前选择 14.44：开发者认为它与 14.42 的性能几乎无异，对新应用的兼容性更好。新版安装与修复只提供 14.44，14.42 已过时，不再提供其安装包。

主页和运行库页的颜色是项目兼容性策略提示，不等同于已证明 DLL 损坏或游戏必然掉帧。检测失败会显示“待核对”；安装登记也不能证明 DLL 完整性。先刷新检测并阅读诊断，再选择符合问题范围的操作。

| 检测结果 | 颜色与含义 |
| --- | --- |
| 已核验的 14.44.x 组件 | 绿色，当前推荐版本。 |
| 其余实际安装的 14.50.x、14.51.x，或名称含 Visual C++ v14 的组件 | 红色，按本工具的游戏兼容性策略提醒。 |
| 已核验的 14.42.x，且未命中前述红色规则 | 黄色，已过时，建议改用 14.44。 |
| 其他非 14.44 的已安装 14.x 组件 | 黄色，版本提醒。 |
| 未检测到已安装的 14.x 运行库 | 红色缺失警告，可能影响游戏启动；检测失败时只保留待核对。 |

卸载列表的包装登记或残留条目本身最高只作黄色提醒，不能代替实际已安装组件；Windows 的 Appx 系统组件包也不能代替游戏需要的 Win32 运行库。

- 「预览并仅修复 14.x」用于维护 C++ 2015–2022 x86/x64 14.x；页面会预览后续步骤。开始前关闭游戏和其他应用，并按页面说明临时关闭运行库防护。
- 「预览全量修复」覆盖更广的 C++ 组件，可能包含卸载与分阶段安装；仔细阅读每一步，安全模式和正常模式的操作不同。部分安装步骤需要回到正常模式手动继续。
- 运行库防护按安装器文件名在全系统生效，不只影响三角洲。需要手动运行微软安装器时，先关闭防护，完成后再按需恢复。
- 「强制替换 14.x DLL（高风险）」会把系统目录中的 14.x DLL 替换为内置 14.44 版本，可能把较新文件降级并需要重启。它不是日常修复首选；只有确认普通修复无法解决且理解影响时才使用。页面会先预览并要求显式确认，同时生成备份和恢复脚本。
- 若操作中断或结果未知，使用「核对未完成操作」。核对只确认事务状态，不会再次安装或卸载。共享运行库也可能被其他程序使用，修复后若其他软件要求较新版本，可能需要重新安装其依赖版本。

「仅修复 C++ 14.x」卡片只保留预览修复与强制替换两个操作按钮。停止任务在「修复进度与恢复」区域；安全模式下卸载后，回正常模式展开「恢复与续装」继续安装，临时 Installer 设置的恢复入口也在这里。安全模式不是强制要求，重启后不会自动开始修复。

## 设置、更新与反馈

「设置」包含游戏目标、主题与背景、开机启动、关闭时最小化到托盘、更新方式/服务器/通道、日志、BUG 反馈和恢复入口。

- 更新默认使用自建服务器并仅替换有变化的文件；也可按需选 GitHub、自动模式或全量更新。版本通道选择会影响收到的更新类型。下载与安装由用户确认；只有安装包安装的版本支持应用内自动更新，开发构建或手动解压构建可能需要手动下载。
- BUG 反馈需要填写问题模块和复现步骤。应用日志是可选附件；发送前会提供预览并要求确认。未确认前不会提交。日志目录可从设置页打开。
- 「核对未确认操作」用于处理超时、断线或结果未知的后端请求。超时不等于操作已恢复；先确认相关程序是否已结束，再按页面状态核对。保留证据有助于准确恢复和排查。
- 「恢复出厂设置」会备份当前配置、停止并恢复工具的临时修改，并重置界面、目标、自动功能、进程规则和后台参数。它不会自动撤销已应用的系统优化，也不会清除系统优化备份、日志或插件；需要逐项到对应页面恢复。未完成事务必须先核对，不能用重置跳过。

## 常见问题

**开关打开了，系统设置没变化？** 在「系统优化」中，开关只记录选择；需要再点「应用更改」。其他栏目按各自按钮或确认框执行。

**某个按钮是灰色的？** 可能是游戏运行或状态未知、恢复事务未核对、硬件/驱动不支持，或当前操作需要权限。先查看该页状态和顶部提示，退出游戏后点「重新确认」，不要用别的入口绕过限制。

**清理缓存后第一次进游戏更卡？** 游戏正在重新编译着色器，首局或首次加载地图可能暂时卡顿。等游戏完成编译后再判断。

**状态写着“未知”“待核对”或“部分完成”？** 这不代表操作已成功，也不代表系统已恢复。不要重复运行可能有写入的操作；先使用该页的核对/恢复入口，或到设置页核对未确认操作。

**关闭窗口后工具仍在运行？** 如果帧格或 CPU 调度正在工作，工具可能询问是否留在托盘。按提示正常退出；退出流程会先停止后台功能并处理临时设置。

**如何提供问题信息？** 在设置页打开日志目录，记录问题发生时间，并通过 BUG 反馈填写复现步骤。发送前检查预览内容，确认是否附带日志。

## 建议的日常顺序

1. 主页检查目标和组件状态。
2. 有明确问题时进入对应栏目先查看说明与预览，不要因为红黄颜色或文件数量就清理组件。
3. 每次只调整少量项目，执行后检查状态和实际效果。
4. 使用过临时功能后正常关闭或按页面入口恢复；出现未知结果时先核对记录，保留备份和日志。
