# MCP 本地 Agent 接入（本地实验版）

本次在 Beta0.932-RC1 / 0.9320 发布源码上增加本地 MCP。未发布到更新通道，安装版需要换用含本功能的完整构建目录。原工具功能及六后端执行实现不变。

## 使用

1. 打开含本功能的 `DeltaNFD.exe`；需要修改系统配置时，以管理员身份运行主程序。
2. 正常启动时自动开启接入；可在“设置 → Agent 接入（MCP）”查看状态或关闭本次接入。
3. 点击“复制 Agent 配置”，将 JSON 合并到支持 stdio MCP 的 Agent 客户端配置并重新连接。配置指向本次目录中的 `Tools/Mcp/DeltaNFD.Mcp.exe`。不同客户端的配置入口可能不同；复制的是 `mcpServers` 格式。
4. 让 Agent 先调用 `deltanfd_status` 和 `deltanfd_list_actions`，按目录的 `inputSchema` 提交操作。写入必须在工具主窗口确认。关闭确认窗口、取消或超过三分钟都不开始该次操作。

接入在每次正常启动主程序时默认开启，手动关闭仅影响本次运行，下次正常启动重新开启；没有新增持久开关。维护或恢复模式不自动开启，自动开启失败会在设置页显示原因并允许重试，不使主程序退出。退出主程序会关闭接入，不会在后台留下独立服务。MCP 辅助程序通过标准输入输出与 Agent 通信，通过仅限本机同一用户的命名管道连接主程序；没有 HTTP 端口。辅助程序本身不执行系统优化，也不自动启动或提权主程序。需要保持完整目录，不能只复制 EXE。

如果旧版正在运行，请先自行退出旧版，再打开本次完整目录中的程序；原单实例机制会激活已运行的旧版。普通权限 Agent 和管理员主程序采用实际用户 SID 核对，管道仅允许该用户并拒绝网络访问，设置中等完整性标签；主程序身份只用受限查询权限读取映像与创建时间，不读取管理员进程模块。已验证实际管道权限和标签，尚未做真实跨 UAC / Agent 客户端现场联调；需要管理员功能时提升主程序即可，不要求先把整个 Agent 提权。

## 工具与调用约定

| MCP 工具 | 用途 |
|---|---|
| `deltanfd_status` | 应用版本、管理员、游戏观测、待核对模块和接入状态 |
| `deltanfd_list_actions` | 列出全部动作，或用 `module` 筛选 gpu/system/runtime/ace/procman/app |
| `deltanfd_submit_action` | 提交 `action`、`arguments`、`requestId`，立即返回操作编号 |
| `deltanfd_get_operation` | 使用 `operationId` 查询进度、终态和原后端回执 |
| `deltanfd_cancel_operation` | 取消排队或尚未确认的操作；不会强行结束在途后端或安装器 |

当前显式目录为 **112 项**，覆盖状态查询、NVIDIA 设置和防闪屏重置、着色器维护、ACE、运行库、系统优化、电源/虚拟内存、录制组件以及通用进程控制。`gpu.settings.catalog` 提供 NVIDIA 设置和值；`system.optimizations.catalog` 提供优化库项目与服务组标识。`system.low-memory.status` 返回低内存状态与指纹，`system.low-memory.apply` 沿用原后端的新鲜指纹与逐项核对。

调用示例：先提交 `action: "gpu.driver.status"`、`arguments: {}`、`requestId: "gpu-status-001"`，再用返回的 `id` 查询进度。防闪屏重置为 `gpu.driver.profile-reset`，参数 `{}`；只会在主窗口明确确认后执行。

`queued`、`awaiting_confirmation`、`running` 均不代表成功。终态：

- `completed`：后端报告完成，仍以回执和实际复检范围为准。
- `partial`：存在已知部分完成，读取明细，不能描述为全部成功。
- `failed` / `cancelled`：失败或取消。
- `requires_review`：结果未知或仍有恢复义务，去设置中的原核对流程处理，保留证据，禁止自动重放原写入。

同一次接入内，网络/管道响应丢失后，只能以**相同 requestId 和完全相同参数**重查原提交；不会重复执行。换用不同参数会被拒绝。该去重记录只保留在本次接入，主程序重启或关闭后重新开启接入时，不能依赖旧 requestId 去重，应先核对实际状态。每次接入最多保留256条记录、最多16个未结束操作。

关闭接入会取消排队与待确认操作。已经开始的操作继续沿原后端执行和收尾，仍受原写前记录、进程身份、备份与退出核对约束。进程控制由主程序的原会话持有，不能把断开 Agent 当作已恢复进程属性。

## 保留的边界

- 仍使用原 `BackendCaller/BackendClient`、模块互斥、紧急策略、写前意图、未确认记录与恢复入口。系统/GPU/ACE/运行库操作保留游戏退出和未知状态拒绝，并在启动、发送前复核。写入要求管理员主程序。
- 写入参数必须显式提供目录列出的顶层字段，未知字段、重复字段、类型错误、越界和超限参数拒绝。Agent不能传入已知悉 ReBAR 警告的标记；该确认由主程序按当时驱动版本产生，执行前再次核对版本。
- 公测隐藏的钟摆/忽略精度项目、原始后端启动/停止、低层恢复/归档、临时 Defender 排除项、直接显卡重载等内部步骤未作为任意命令开放。没有 shell、任意注册表或文件写入接口。
- 帧格开启/退出复用原 `FrameModeFlow`，包括原确认、恢复及重启选择。由于原流程只返回界面交互结果，MCP保守返回部分结果与总开关/快照，不把总开关达到目标当作全部子项成功。
- 原游戏目标、运行库功能开关和≤16GB内存不开放关闭压缩/分页合并的规则保留。完整功能清单以实际 `deltanfd_list_actions` 为准。

## 开发与验证

`src/DeltaNFD.Mcp` 使用官方 C# MCP SDK 2.4.0。`DeltaNFD.AgentBridge` 只含协议、目录、校验和任务队列，不引用执行库。WinUI 主程序负责确认与调用原后端。构建/发布主程序会将自包含 MCP 宿主放入 `Tools/Mcp`，可用 `BuildMcpHost=false` 跳过辅助程序构建。

专用检查在 `tools/McpBridgeChecks`。核心队列、权限/游戏/低内存门禁检查使用模拟执行；协议检查启动自有模拟主程序，验证真实 SDK stdio 握手、工具调用和 Windows 命名管道，不执行真实系统/GPU写入。正式GUI、真实优化实效与用户 Agent 客户端设置需另行现场验收。

查询错误会把已知的参数、权限、接入未开启等原因返回 Agent。连接中断或超时会明确提醒先查询原操作或核对实际状态，不把连接失败当成未执行。辅助程序已在空 PATH / 空系统 .NET 目录的进程环境中通过协议检查。
